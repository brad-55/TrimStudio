# 音声トラック機能（音ズレ解消・追加・自動同期・選択）計画 v0.1

作成: 2026-11-07 / 対象: TrimStudio（app/exports.py, app/main.py, web-qwen/index.html）

## 1. 目的

無劣化トリミングに加えて、音声トラックを扱えるようにする。

| # | 機能 | 内容 |
|---|---|---|
| F1 | 音ズレ解消 | 元の音声トラックを指定時間ずらす（ms 単位、正負） |
| F2 | 音声トラック追加 | 別の動画または音声ファイルから音声トラックを追加する |
| F3 | 追加音声の音ズレ解消 | 追加した音声を指定時間ずらす。**可能なら自動同期**（元音声に合わせる） |
| F4 | 音声トラック選択 | 元のみ／追加のみ／同時／消音 を選ぶ |

## 2. 現状の書き出しパイプライン（前提）

- 映像: パケットコピー（無変換）または再エンコード。3パス（映像単体 → 音声等 → 多重化）で回転・形式を処理。
- 音声: `build_audio_copy_args`（パケットコピー）または `build_audio_reencode_args`（AAC 等へ再エンコード）。
- 多重化: `_mux_args`（itsoffset / map / copy / avoid_negative_ts make_zero）。
- 出力名: `export_tags(options, start, end)` がモードと指定内容を `切出..._無変換_...` の形で作る。
- 画面: 音声再エンコードのチェックとビットレートのみ。

## 3. 無変換の保証（設計の柱）

**F1・F2・F4 の「元のみ／追加のみ／2トラック保持」はパケットコピーのまま**で、音声データはビット単位で保持する。変えるのはタイムスタンプとトラック構成だけ。

| 操作 | 実現方法 | 無変換 |
|---|---|---|
| 音声を +Δ 遅らせる | 音声パケットのタイムスタンプを +Δ（先頭に Δ の無音ギャップ） | ○ パケットは無変更 |
| 音声を −Δ 早める | **映像側**のタイムスタンプを +Δ（結果として音声が Δ 先行。先頭に Δ のギャップ） | ○ パケットは無変更 |
| 追加トラック | 2本目の入力を `-c copy` で多重化（自トラックの先頭を IN に合わせ、shift を加算） | ○ |
| 同時使用（ミックス） | `amix` で1本にまとめる → **音声のみ再エンコード** | ✗ 画面で明示 |

- **負のずらし**は「音声を前へ出す」＝「映像を後ろへ送る」と等価。パケットを捨てずに済み、ずらし量も連続値で正確（音声フレーム長に量子化されない）。
- **正のずらし**もタイムスタンプのみの変更で、無音ギャップはコンテナが表現する（MP4 は編集リスト、MKV はそのまま）。
- ずらし量は**ミリ秒単位の整数**（1ms 刻み）。丸めは行わず、タイムスタンプにそのまま反映する。

## 4. 機能設計

### F1 元音声のずらし
- パラメータ: `audioShiftMs`（整数、既定 0）。範囲は **-5000〜+5000ms**（それ以上は入力可だが警告）。
- UI: 数値入力 + ±1ms / ±10ms / ±100ms ボタン + スライダー。現在値の隣に「音声を 120ms 遅らせる」のような説明を出す。
- 出力名タグ: `_音声+120ms` / `_音声-120ms`（0 のときは付けない）。

### F2 音声トラック追加
- 追加できるのは**1本**（将来複数に拡張できるデータ構造にする）。
- 取得方法: 既存の PC エクスプローラ（`check_path` で許可ルート内のみ）またはアップロード。`sources.open` / `upload` を再利用し、Source として持つ。
- 追加トラックは**映像の IN 点に自トラックの先頭を合わせる**。動画長・音声長が足りない場合は足りない分を無音にする（警告を表示）。
- 詳細設定として**追加ファイル内の開始位置**（既定 0）を指定できるようにする（長い素材の途中を使う場合）。
- コンテナ互換: 追加トラックのコーデックが出力コンテナに入らない場合は、その時点で **400 invalid_container**（理由付き）。「音声のみ再エンコードして追加する」選択肢も用意する（非無変換と明示）。
- 出力名タグ: `_追加音声`。

### F3 追加音声のずらしと自動同期
- `addedShiftMs`（整数、既定 0、範囲 -5000〜+5000ms）。仕組みは F1 と同じ（追加トラック側に適用）。
- **自動同期**: 元音声と追加音声の相互相関で遅れを推定する。
  - 解析: 両者から **16kHz モノラル PCM** を、IN 点を基準に最大 60 秒ぶん抽出（`ffmpeg -ss -t -vn -ac 1 -ar 16000 -f s16le`）。
  - 推定: `numpy` の FFT で相互相関（GCC-PHAT 方式）。探索範囲は**±5000ms**。ピーク位置を遅れ、ピークと第2ピークの比を**信頼度**として返す。
  - 判定: 信頼度がしきい値未満、または音声がほぼ無音の場合は「自動同期できませんでした。手動で合わせてください」と表示し、値を書き換えない。
  - 実行: 解析は**ジョブ**として非同期実行（`POST /api/audio/sync` → `{jobId}` → `GET /api/jobs/{id}` に `offsetMs` / `confidence` を載せる）。画面には進捗と「解析中」を表示。
  - 解析結果は表示するだけにせず、**「この値を使う」ボタン**で `addedShiftMs` に反映する（自動で書き換えない）。
- 出力名タグ: `_追加音声-60ms`。

### F4 音声トラックの選択（audioMode）
| 値 | 表示 | 中身 | 無変換 |
|---|---|---|---|
| `original` | 元の音声のみ（既定） | 元音声1本（+shift） | ○ |
| `added` | 追加した音声のみ | 追加音声1本（+shift） | ○ |
| `bothTracks` | 両方を残す（2トラック） | 元＋追加の2本。プレーヤーで選んで聞く | ○ |
| `bothMix` | 同時に鳴らす（ミックス） | amix した1本。**音声のみ再エンコード** | ✗ |
| `mute` | 消音（音声なし） | 音声ストリームを出さない | ○（映像はそのまま） |

- 既定は `original`（＝従来と同じ）。
- `bothMix` を選んだ瞬間に「音声のみ再エンコードされます（映像は無変換）」と画面に表示する。ミックスの音量バランスは既定 1:1（`normalize=0`、クリップ時は警告）。

## 5. 画面設計（web-qwen）

書き出し設定の中に「音声」節を追加（無変換／再エンコードのどちらでも使える）。

```
[音声]
 ( ) 元の音声のみ   ( ) 追加した音声のみ   ( ) 両方（2トラック）
 ( ) 同時に鳴らす（音声のみ再エンコード）   ( ) 消音

 元の音声のずらし:  [ -100 ] [ -10 ] [ -1 ]  120 ms  [ +1 ] [ +10 ] [ +100 ]
                    [=========|=========]  スライダー ±1000ms

 追加する音声:      [ PC から選択 ] [ アップロード ]   (ファイル名: ... / 長さ 3:21)
 追加音声のずらし:  [ -100 ] [ -10 ] [ -1 ]  -60 ms  [ +1 ] [ +10 ] [ +100 ]
                    [ 自動同期 ]  → 解析中… / 推定 -137ms（信頼度 0.82）[ この値を使う ]
 追加ファイル内の開始位置: 0.000 s

 [ 音を確認して合わせる ]  ← 追加音声を映像と一緒にその場で再生（ずらしを即反映）
```

- **その場で試聴**: 追加音声は 2 つ目の audio 要素（`/api/sources/{id}/media` は Range 対応）で再生し、`video.currentTime` に対して ```@(audioShiftMs - addedShiftMs)```@ を足した位置を追従させる。ずらしを変えたら即座に反映する。ミックスは試聴せず（再エンコードが必要なため）、注意文のみ。
- 追加音声の選択は既存のエクスプローラ UI を再利用する。

## 6. API 追加・変更

- `POST /api/exports` の options に追加:
  `{ audioMode: "original"|"added"|"bothTracks"|"bothMix"|"mute", audioShiftMs: int, addedSourceId: str, addedShiftMs: int, addedStartMs: int, addedReencode: bool }`
- `POST /api/audio/sync` `{ sourceId, addedSourceId, startUs, windowMs=60000, rangeMs=5000 }` → `{ jobId }`（ジョブ結果に offsetMs / confidence / reason）
- `GET /api/sources/{id}` は変更なし（追加ファイルも同じ Source として扱う）
- 既存の検証（許可ルート・CSRF・Host・LAN/tailnet）をそのまま適用。追加ファイルも読み取りのみ。

## 7. ファイル名タグ

```

音声ずらし:  元名_切出0s-2s_無変換_音声+120ms.mp4

```

## 8. 制約・エラー

- **ミックス（bothMix）だけが非無変換**（音声のみ）。画面とファイル名の両方で分かるようにする。
- コンテナ非対応（PCM を MP4 に入れる等）は 400 invalid_container（理由付き）。「音声のみ再エンコード」を案内する。
- 追加ファイルが短い場合は足りない分を無音にし、警告を出す（エラーにはしない）。
- 音声ストリームを持たないファイルを追加しようとした場合は 400 invalid_audio（理由付き）。
- ずらしが動画長を超える場合は警告（結果が無音になるため）。
- 追加ファイルも許可ルート内・動画/音声拡張子のみ（既存の制限を継承）。
- 自動同期は**無音・音楽のみ・別内容**では失敗しうる。失敗時は値を変えず、手動調整を促す。

## 9. テスト計画（客観的に測れる形にする）

**単体（tests/test_unit.py / 新規 test_audio.py）**
- 引数生成: +Δ／−Δ のタイムスタンプの向き、追加入力の `-map`、コンテナ互換の判定、ずらし0のとき引数が従来と同一であること。
- タグ生成: 上記 6 パターンの文字列。
- 自動同期の計算部分（相互相関）を純関数化し、既知の遅れを与えた合成波形で推定値を検証（137ms を ±1 サンプル以内）。

**E2E（新規 tests/e2e_audio.py）**
- 素材: 既知の時刻にビープ音を入れた合成動画（ffmpeg で生成）。
- (1) 回帰: 音声オプションなしの出力が従来と同一（音声ストリームの MD5 一致）。
- (2) +120ms: 音声パケットが**ビット一致**（`-f md5` が元と一致）で、コンテナ上の音声開始が +120ms。
- (3) −120ms: 音声パケットはビット一致で、映像の開始が +120ms。
- (4) 追加トラック: 出力の音声ストリームが 2 本、追加分のコーデック・長さ・開始位置を ffprobe で確認。
- (5) 自動同期: 人工的に 137ms 遅らせた追加音声で、推定が 137±23ms に入り confidence が返る。
- (6) bothMix: 音声1本・再エンコードされ、両方の周波数成分が混ざっている（FFT で確認）。
- (7) mute: 音声ストリームが無い。
- (8) 非対応コンテナ: 400 invalid_container と理由。
- (9) ftyp/長さ/デコードエラー0（既存の e2e_lossless と同じ観点を維持）。

**静的・スモーク**: 画面の音声節の要素、`audioMode` の 5 値、試聴の同期式、危険な文字列が入っていないこと。

# 追補 v0.2（第49ラウンドのレビュー指摘を反映）

## 1. −Δ（音声を早める）の MP4 互換性を確定（重大1）

方針は「映像側を +Δ 遅らせる」のまま（音声に負の PTS を作らない標準的な回避策）。実装と検証を次に固定する。

- **実装**: ずらしは多重化段で `-itsoffset` を用い、対象の入力を指定する。
  - +Δ（音声を遅らせる）: `-itsoffset Δ` を**音声入力**に適用。
  - −Δ（音声を早める）: `-itsoffset |Δ|` を**映像入力**（および字幕）に適用。
  - ずらしを行うパスでは `-avoid_negative_ts` を **disabled**（または未指定）にし、`make_zero` を使わない。make_zero は最小タイムスタンプを 0 に寄せるため、ギャップが消えてしまう。
  - mov muxer は `-use_editlist 1` を明示し、MP4 には編集リスト（elst）を必ず書かせる。
- **検証（E2E に必須項目として追加）**:
  1. `ffprobe -show_entries stream=index,codec_type,start_time` で音声／映像の開始時刻が期待どおり（+Δ なら音声が +Δ、−Δ なら映像が +Δ）。
  2. **MP4 を自前で解析して elst の存在と media_time を確認**（moov→trak→edts→elst を読む小さなパーサを tests に置く）。elst が無ければ不合格。
  3. MP4 と MKV の両方で −Δ を検証。
  4. 先頭フレームのデコード（`ffmpeg -v error -i out -frames:v 1 -f null -` のエラー 0）と、長さが範囲どおりであること。
- MKV/WebM は絶対タイムスタンプのため同じ手法で成立する（elst 不要）。

## 2. bothMix（amix）の詳細を確定（高2）

- フィルタ: `[0:a][1:a]amix=inputs=2:duration=longest:dropout_transition=0:normalize=0[a]`
  - **`normalize=0` を明示**（既定の正規化で約 -6dB になるのを防ぐ）。音量バランスは既定 1:1。
  - クリップの可能性があるため、画面に「音量が大きいと割れることがあります」と注記する。
- サンプルレート・チャンネル: 元音声の形式に合わせる。
  - 追加側に `aresample=<元のサンプルレート>` と `aformat=sample_fmts=fltp:channel_layouts=<元のレイアウト>` を適用。
  - 元がモノラルなら、追加側をモノラルに落としてから混ぜる（アップミックスしない）。
  - 元のレイアウトが取得できない場合は 48kHz ステレオにする（この場合だけ既定にフォールバック）。
- 出力の音声コーデックは既存の音声再エンコード規則（コンテナ別: mp4系=aac 等）に従う。ビットレート未指定なら元音声のビットレートを踏襲。

## 3. 自動同期の解析条件と符号規約（高3）

- **抽出長**: `windowMs + 2 * rangeMs` を**両方の素材から**抽出する（既定: 60000 + 2×5000 = 70000ms）。探索範囲の端で相関が切れないようにする。
- **基準点**: 元動画は IN 点から、追加素材は `addedStartMs` から抽出し、その位置関係を戻り値に反映する。
- **符号規約**: `offsetMs` は「**追加音声をこの値だけ遅らせると元音声に合う**」とする（正 = 追加音声を遅らせる）。
  - 「この値を使う」を押すと `addedShiftMs = offsetMs` を設定する（符号の反転はしない）。
- **信頼度**: ピーク/第2ピーク比に加えて、**正規化相互相関の最大値（0〜1）**も返す。両方がしきい値未満（比 < 1.5、または相関 < 0.15）なら失敗として扱い、値を変えず「自動同期できませんでした。手動で合わせてください」と表示する。
- **UI の注記**: 「音楽のみ・無音・内容が違う音声では自動同期できません」を常時表示する。

## 4. 試聴の同期式を確定（高4）

- 再生式: `audio.currentTime = addedStartMs/1000 + (video.currentTime - inUs/1e6) - (audioShiftMs + addedShiftMs)/1000`
  - 導出: 書き出しでは、元音声が `in+τ+S1` の内容、追加音声が `A0+τ-S2` の内容を同時に鳴らす。試聴では映像の音声が `in+τ`（＝シフトなし）で聞こえるため、追加側を `(S1+S2)` だけ手前へずらして**書き出しと同じ相対関係**を再現する。
  - `addedStartMs` を必ず加算する（追加ファイル内の開始位置）。
- **元音声のミュート**: audioMode が `added` / `bothTracks` のときは「元の音声を消して聞く」トグルを出し、既定で video をミュートする（追加音声だけを確認できるようにする）。
- **ドリフト補正**: `timeupdate` ごとに期待位置と実位置の差を監視し、80ms を超えたら `audio.currentTime` を再設定する。再生開始・シーク・ずらし変更のたびに即時再同期する。

## 5. 追加音声のコンテナ互換を「コンテナ＋コーデック」で判定（高5）

- 既存の `copy_compatibility(st, container)` を追加ストリームにも適用し、**コンテナだけでなくコーデックまで**見る。
- 代表例: Vorbis→MP4（不可）、Opus→MP4（不可扱い。WebM/MKV のみ許可）、PCM→MP4（不可）、AAC→MKV/MP4/MOV（可）、MP3→MP4（可）。
- 不可の場合は出力を作らず **400 invalid_container**（理由つき）。画面には「音声のみ再エンコードして追加する」チェック（非無変換の明示）を出す。
- `bothTracks` でも同じ判定を行う（2本目だけ落として黙って成功させない）。

## 6. 字幕・チャプターの扱い（中6）

- Δ≠0 のときは、**映像・字幕・（添付を除く）映像側の全ストリームをまとめて +Δ** する（音声との相対関係だけを変える）。
- **チャプターは Δ≠0 のときコピーしない**（ストリームコピーでは時刻を確実に移せないため）。画面に「チャプターは引き継がれません」と表示する。Δ=0 のときは従来どおりコピーする。

## 7. 長さ・境界のクランプ規則（中7・中8・Flash 指摘）

- 追加音声が長い場合は**書き出し範囲で打ち切る**（映像の範囲が出力の長さを決める。追加音声の残りは入らない）。
- 追加音声が短い場合は足りない分を無音にし、警告する（エラーにしない）。
- `addedStartMs + max(0, -addedShiftMs) <= 追加ファイル長` を満たすようクランプし、超える場合はクランプした旨を表示する。
- 追加音声の先頭が書き出しの先頭より前になる場合（負のずらし）は、**追加ファイル側の先頭を |Δ| ぶん読み飛ばす**（元音声の負のずらしと同じ考え方。負の PTS を作らない）。
- 出力の長さは常に [IN, OUT] と一致させる（`-t` で明示。`-shortest` は使わない。理由: 音声だけ短い場合に映像が切られるのを避けるため）。

## 8. UI の補足（低11）

- audioMode が `mute` / `added` のときは「元の音声のずらし」をグレーアウトし、「このモードでは使いません」と表示する。
- 追加音声を選んでいないときは追加音声関連の操作を無効化する。
- `bothMix` 選択時のみ「音声のみ再エンコード」の警告を常時表示する。

## 9. 追加するテスト（中9）

E2E に次を追加する。

- MP4 と MKV の両方で −Δ（開始時刻・elst の有無・デコードエラー0・長さ）。
- B フレームを含む映像での ±Δ（映像パケットはビット一致、開始時刻のみ変化）。
- 音声のみのファイル（mp3）を追加トラックにする。
- サンプルレート・チャンネル数が違う素材の `bothTracks`（互換判定）と `bothMix`（aresample/aformat が効いていること）。
- `addedStartMs` を指定した追加（開始位置が出力に反映されること）と、範囲外指定のクランプ。
- 追加音声が短い場合の無音埋めと、長い場合の打ち切り。
- 字幕・チャプター付き素材での Δ≠0（字幕が映像と一緒に移動し、チャプターが落ちること）。

# 追補 v0.3（第50ラウンドの指摘を反映）

## 1. ずらしの適用範囲を確定（中1）

- **`audioShiftMs`（F1）は元の音声トラックにのみ適用する。追加トラックには適用しない。** 追加トラックは `addedShiftMs`（F3）だけで制御する（合計値 S1+S2 は使わない）。
- したがってクランプ条件も `addedStartMs + max(0, -addedShiftMs) <= 追加ファイル長` のままで正しい。
- 理由: F1 は「元音声のずれ」、F3 は「追加音声のずれ」で独立した問題であり、シーン（映像）を基準にそれぞれ合わせるべきだから。

## 2. 試聴の方式を確定（中1・低2）

- 映像要素の音声は**ミュート**し、**音声要素を2つ**使って書き出しと同一の組み合わせを再現する。
  - 元音声用: `orig.currentTime = video.currentTime - audioShiftMs/1000`
  - 追加音声用: `added.currentTime = addedStartMs/1000 + (video.currentTime - inUs/1e6) - addedShiftMs/1000`
  - 導出: 書き出しでは、時刻 τ に「元音声は (in+τ−S1) の内容」「追加音声は (A0+τ−S2) の内容」を鳴らす。試聴でも同じ内容を同時に鳴らせば、同じ組み合わせが聞こえる。
- `currentTime` は **0 未満にしない**（`Math.max(0, ...)`）。
- 再同期は `timeupdate`（約4Hz）だけに頼らず、`requestAnimationFrame` で毎フレーム監視し、期待位置との差が **80ms** を超えたら再設定する。再生開始・シーク・ずらし変更・モード変更で即時再同期する。
- 「元の音声を消して聞く」トグルは、元音声用の音声要素の音量を 0 にする（映像は常にミュート）。

## 3. 追加するテスト（中2・中3・低1・低3・低4）

- **F4（トラック選択）の E2E**: 音声トラックを2本持つ素材を用意し、選択したトラックだけが出力に残ることを ffprobe（ストリーム数・コーデック・言語タグ）で確認する。
- **bothMix × Δ≠0**: `-itsoffset` が filter_complex（amix）の入力タイムスタンプに効くかを E2E で確認する。効かない場合はフィルタ内で `adelay` / `asetpts` に切り替える（その旨を実装メモに残す）。
- **elst の media_time**: 存在確認だけでなく、`media_time` が期待値（|Δ| 相当の timescale 換算）と一致することを確認する。
- **自動同期の失敗パス**: 無音・音楽のみの素材で、値を変更せず「失敗」を返すことを確認する。
- **400 invalid_container**: Vorbis→MP4、PCM→MP4、Opus→MP4 の3件を確認する。
- **Opus→MP4 を不可とする理由**を計画に明記: 技術的には格納できるが、再生互換性の低いプレイヤーが多いため製品判断として不可とし、WebM/MKV のみ許可する（音声のみ再エンコードの選択肢を案内）。

# 追補 v0.4（実機検証の結果と最終メモ）

## 1. 実機検証（ffmpeg 9.0.2 / この PC） — 計画の最大リスクを解消

合成素材（320x240 30fps + 48kHz AAC、2秒）で多重化だけを試した結果（review/audio_shift_probe.py）:

| ケース | 映像 start_time | 音声 start_time | elst | 音声 MD5 | デコードエラー |
|---|---|---|---|---|---|
| 元 | 0.000000 | 0.000000 | — | 8028...587 | 0 |
| +120ms（音声入力に itsoffset） | 0.000000 | **0.098667** | 両トラックにあり（空編集あり） | **元と一致** | 0 |
| −120ms（映像入力に itsoffset） | **0.119987** | 0.000000 | 両トラックにあり（空編集あり） | **元と一致** | 0 |
| −120ms（MKV） | **0.120000** | 0.000000 | 不要 | **元と一致** | 0 |

- **無変換は実測で確認**: ずらしても音声パケットの MD5 は元と完全一致（再エンコードされていない）。
- **MP4 は編集リスト（elst）が自動生成される**（空編集 ＋ メディア編集）。`-use_editlist 1` は既定挙動で問題なく機能する。
- **ずらし量の粒度**: 音声はずらし量そのものではなく**音声フレーム境界に量子化**される（AAC 48kHz で 1024 サンプル = 21.33ms。120ms 要求 → 98.667ms 開始）。映像も同様にフレーム境界の影響を受ける（120ms 要求 → 119.987ms）。
  - したがって計画中の「連続値で正確」は**「音声フレーム長（約21ms）以内の精度」に読み替える**。1ms 刻みの UI は維持する。
  - **E2E の合否基準は「要求値との差が音声フレーム長以内（≤ 23ms）」**とする（厳密一致は求めない）。音声パケットのビット一致は厳密に検証する。

## 2. 試聴の細部（GLM の minor 指摘）

- `video.currentTime - IN < 0`（IN より前を再生中）のときは、追加音声要素を **pause + mute** し、currentTime を 0 にクランプして鳴らさない（早く鳴ってしまうのを防ぐ）。
- 元音声要素も `video.currentTime - S1 < 0` のときは pause する（内容位置が負になる区間）。
- `requestAnimationFrame` はタブ非表示で止まるため、`visibilitychange`（表示に戻ったとき）と `seeked` / `play` で再同期する。
