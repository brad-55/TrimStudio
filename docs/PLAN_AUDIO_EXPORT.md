# 音声機能 書き出し配線 実装計画 v0.16

親計画: docs/PLAN_AUDIO.md（v0.1〜v0.4）。v0.5〜v0.16 は三者レビュー（Gemini 4 Argon / GLM 5.3 Flash / Qwen）の指摘反映。

## 0. 決定事項（レビュー指摘の解消）

### 0.1 出力長の定義
出力の長さは常に「要求した IN–OUT 区間」に一致し、**ずらしによって変化しない**。原則: 出力の長さは要求区間長に一致する。ただし**音声/字幕のみのパケットコピーで素材が短い場合はこの例外**（下記）が優先する。映像があれば映像パケットが長さを定義する。音声/字幕のみの場合はカットの `-t` が上限を与えるが、**パケットコピーでは無音パディングができないため、素材（追加トラック等）が短い場合は出力長が短くなる**（0.10）。

### 0.2 ずらしオフセットの厳密な規則（**v0.6 の誤りを修正**）
すべてのオフセットは**「映像を基準（video-relative）」**で定義する（試聴の式と同じ基準）。

| 入力 | itsoffset に加える値 | 意味 |
|---|---|---|
| video（= video_off） | **映像かつ元音声が出力にある場合のみ** `max(0, -Δ_orig)`、それ以外は `0` | Δ_orig<0 のとき映像・字幕を後ろへ送り、相対的に元音声を前へ出す |
| audio（元） | `max(0, +Δ_orig)` | Δ_orig>0（元音声を遅らせる） |
| added（追加） | **`video_off` + `max(0, Δ_add)`** | 追加トラックも基準ストリーム基準で配置する（video_off は上表の条件付き値） |

- **重要（v0.6 までの誤り）**: 既存の audio_offsets() は added に max(0, Δ_add) しか足しておらず、**Δ_orig<0 のとき追加トラックが |Δ_orig| だけずれる**。
  ヘルパーは次のように修正する: **added = video_off + max(0, Δ_add)**。ここで video_off は 0.8b の表で計算した映像オフセットであり、
  **映像と元音声の両方が出力に含まれる場合（ケース1）のみ非 0**、それ以外（ケース2・3・4）は 0 である（ケース3は映像が無いため video_off は存在しない）。
  したがって元音声を含まないケースで生の max(0, −Δ_orig) を足してはならない。
  単体テストは (Δ_orig<0 ∧ Δ_add≠0 ∧ 元音声あり) と (Δ_orig<0 ∧ 元音声なし = ケース2) の両方を追加する。
- 追加トラックの負のずらし（Δ_add<0）は、切り出し時の **head_skip**（`added_head_skip_us`）で先頭を落として吸収し、mux オフセットは 0 未満にしない。
- ずらし時は全パスで `-avoid_negative_ts disabled`（**make_zero 禁止**）、MP4/MOV/iPod は `-use_editlist 1`。Δ=0 のときのみ従来どおり `make_zero` + `-map_chapters 0`。

### 0.3 bothTracks は 3 入力 mux
映像＋元音声＋追加音声を**明示 `-map`** で多重化する。`_shifted_mux_args3()` を新設（入力ごとに 0.2 の値を適用）。
- `-c copy` を全体に適用し、**元音声は必ずコピー**（`-c:a:0 copy` 相当）。
- 追加を再エンコードする場合（addedReencode）も、元音声トラックのコピーは維持する。

### 0.4 bothMix は 2 パス
映像は既存の `_video_cut_args`（コピー）で切り、**音声の生成・結合のみ別パス**にして最後に mux する（既存の映像経路と境界・タイムスタンプ処理を乖離させない）。
- Δ の適用はフィルタで行う（amix は負の遅延を表現できないため）:
  - Δ>0: `adelay=Δ:all=1`
  - Δ<0: `atrim=start=|Δ|` + `asetpts=PTS-|Δ|/TB`
- `amix=inputs=2:normalize=0:duration=longest` を明示。
- **映像には itsoffset を付けない**（ずらしは音声フィルタ側で完全に吸収し、映像タイムスタンプは 0 起点のまま保つ）。
- **bothMix では head_skip を使わない**（二重カット防止）。追加トラックの切り出しは addedStartMs のみとし、Δ_add<0 は追加入力への atrim+asetpts のみで適用する。
- 音声のみ × bothMix では 0.8b ケース 3 により **Δ_orig は無視**される（Δ_orig を音声フィルタへ適用しない。追加音声への Δ_add のみ適用）。
- ずらしは入力ごとに別々に適用する: 元音声に Δ_orig、追加音声に Δ_add（Δ_add<0 は追加入力への atrim+asetpts、Δ_orig<0 も同様に atrim+asetpts）。
- 音声は再エンコードのため**無変換保証の対象外**（警告に明記）。
- チャプター: **コピーしないのは「ケース1 かつ Δ_orig≠0（itsoffset 経路）」および「0.7 経路で Δ_orig≠0」のときだけ**。Δ_add のみが非 0 ならコピーする。
- **例外（bothMix = フィルタ経路）**: 0.4 のとおり映像に itsoffset を付けず映像タイムスタンプが不変であるため、**ケース1・Δ_orig≠0 でもチャプターをコピーする**（削除する根拠が無い）。

### 0.5 addedReencode
true のときは**追加トラックのみ** AAC へ再エンコードしてから mux する。元音声の無変換は維持。追加トラックは元ファイルとのパケット一致の対象外（警告に明記）。

### 0.6 mute と audioTiming=false
「消音」は音声モードの選択であり**タイミング調整とは独立**。audioTiming=false でも mute は維持。mute のときはずらしを無視する。プレビューは audioTiming=false のとき通常再生（消音はプレビューに適用しない）。

### 0.7 音声/字幕のみの入力 × Δ≠0
映像入力が無いため、Δ<0 は「映像に offset」を使えない。単一パスで**音声入力に負の itsoffset** を適用し、`-avoid_negative_ts disabled` + `-use_editlist 1` を使う。
- **コンテナ依存**: 負の開始時刻の表現は elst（MP4 / MOV / iPod）に依存する。WAV / MP3 など elst を持たないコンテナでは負のずらしを表現できず、**黙って無視される恐れ**がある。
- したがって **elst を持たないコンテナでの音声のみ × Δ<0 は 400 で明示拒否**する（無言の成功にしない）。E2E 3 は elst 有（mp4）と elst 無（wav/mp3）の両方で検証する。

### 0.8 オフセット割当の完全定義（ケース別表・v0.8 の矛盾を修正）
**前提**: Δ_orig は「映像に対する元音声のずらし」、Δ_add は「基準ストリームに対する追加音声のずらし」。
**映像が出力に無い場合の Δ_orig の扱いは 0.8b の表に従う**（音声のみ × original は 0.7 を適用し、追加トラックが関与する音声のみ出力では無視して警告「映像が無い出力では audioShiftMs を無視しました」を出す）。

| # | 映像 | 元音声 | vid off | orig off | added off | head_skip |
|---|---|---|---|---|---|---|
| 1 | あり | あり | max(0,−Δ_orig) | max(0,+Δ_orig) | vid off + max(0,Δ_add) | max(0,−Δ_add) |
| 2 | あり | なし（added のみ） | 0 | — | max(0,Δ_add) | max(0,−Δ_add) |
| 3 | なし | あり（bothTracks / bothMix） | — | 0 | max(0,Δ_add) | max(0,−Δ_add) |
| 4 | なし | なし（added のみ） | — | — | max(0,Δ_add) | max(0,−Δ_add) |

- ケース 2〜4 では Δ_orig を無視（警告）。Δ_orig を適用するのは映像が出力に含まれるケース 1 のみ。
- head_skip は追加トラックの切り出し時に先頭 max(0,−Δ_add) を除去する（mux オフセットは負にしない）。
- チャプター: **コピーしないのは「ケース 1 かつ Δ_orig≠0」および「0.7 経路で Δ_orig≠0」のときだけ**。Δ_add のみが非 0 の場合はコピーする。**ただし bothMix（フィルタ経路）は映像 TS が不変のためケース1・Δ_orig≠0 でもコピーする**（0.4）。
- **API ドキュメントに明記**:「audioShiftMs は映像に対するずらし。**音声のみ × original（0.7）を除き、映像が無い出力では無視**。addedShiftMs は基準ストリーム（映像、無ければ元音声、無ければコンテナ時刻 0）に対するずらし」。

### 0.8b モード別の対応表（0.7 と 0.8 の矛盾を解消）
「音声のみ出力」のときの Δ_orig の扱いをモードで確定する。

| audioMode | 映像 | 元音声 | 適用ケース | Δ_orig の扱い |
|---|---|---|---|---|
| original | あり | あり | 1 | 適用（0.2 の式） |
| original | なし（音声のみ） | あり | **0.7** | **適用**（音声入力に正負の itsoffset + avoid_negative_ts disabled + elst） |
| added | あり | なし | 2 | 無視（警告） |
| added | なし | なし | 4 | 無視（警告） |
| bothTracks | あり | あり | 1 | 適用 |
| bothTracks | なし | あり | 3 | **無視（警告）**（基準が元音声のため） |
| bothMix | あり | あり | 1 | 適用（フィルタで実現） |
| bothMix | なし | あり | 3 | 無視（警告） |
| mute | 任意 | — | — | 無視（さらに音声なし出力。ずらしを無視した旨を警告に含める） |

- つまり **Δ_orig が有効なのは「映像がある場合」と「音声のみ × original」の2つだけ**。追加トラックが関与する音声のみ出力では、基準が元音声（またはコンテナ時刻0）になり Δ_orig は定義できないため無視する。
- E2E 3（音声のみ × original × Δ正負）と E2E 13（音声のみ × added/both × Δ_orig 無視）はこの表を前提とする。
- bothMix の Δ は入力構成でケース 1/3/4 に帰着し、いずれもフィルタ（adelay / atrim+asetpts）で実装する。

### 0.9 出力長の強制（0.1 との整合）
音声プランが有効な経路（ずらし / 追加トラック / ミックス）でのみ、最終 mux に **-t = 要求区間長** を指定して 0.1 を機械的に保証する。
- **Δ=0 かつ追加なしの既存経路には -t を付けない**（既存の無変換 E2E のビット一致を壊さないため）。
- 音声/字幕のみの**単一パス**でも同じ規則を適用する（そのパスの出力に -t = 区間長を付ける）。
- これにより bothMix の duration=longest、追加トラックの Δ による張り出し、巨大ずらしによる末尾の余りがすべて区間長で切り落とされる。
- 映像があり音声が区間より短い場合は末尾が無音になる（正常。警告に含める）。**音声のみ出力で短い場合は 0.10 のとおり出力長自体が短くなる**。
- **丸めの許容**: stream copy の -t はパケット境界で丸められるため、出力長は区間長に対して ±1 音声フレーム（AAC 48kHz で ≈21ms）の誤差を許容する。受け入れ基準もこの許容で判定する。

### 0.10 境界クリップの明文化
| 対象 | 規則 |
|---|---|
| 追加トラックの先頭 | addedStartMs を clamp_added_start() で [0, added長] に丸め、Δ_add<0 の分は added_head_skip_us() で先頭を落とす。**ただし bothMix（フィルタ経路）は head_skip を使わず atrim+asetpts で適用する（0.4）** |
| 追加トラックの末尾 | 区間長を超える分は 0.9 の -t で切り落とす |
| 追加が区間より短い | 映像がある場合は途中から無音（正常・警告）。**音声のみ出力で追加が区間より短い場合は、パケットコピーでは無音パディングできないため出力長が短くなる**（正常・警告に「出力が区間より短くなります」を含める。E2E 16 で実測して記録） |
| Δ_add < 0 で head_skip が追加の長さ以上 | 追加は完全に落ちる（警告。invalid にはしない） |
| 元音声が区間外へ張り出す | 0.9 の -t で切る（内容はタイムスタンプどおり） |

## 1. 目的とスコープ
目的: 音声タイミング調整（元音声のずらし／追加トラック／同時2トラック／ミックス／消音）を書き出しに反映する。
対象: 無変換（パケットコピー）経路を主とし、ミックスのみ音声再エンコード。
スコープ外: 映像の再エンコード（既存 reencode モードはそのまま）、自動同期の解析（実装済み）。

1. `audio_offsets()`: **0.2 の修正**（added に video 項を加算）。
2. `plan()`: audioPlan（mode / offsets / added / コンテナ互換 / 出力長）を built に追加。
3. `_shifted_mux_args3()` 新設（3入力・明示 map・入力ごとの itsoffset）。

## 6. 検証計画
### 6.1 単体
- audio_offsets: mode×Δ（**Δ_orig<0 ∧ Δ_add≠0 ∧ 元音声あり** を含む）、**ケース2（added モード・元音声なし・Δ_orig<0 で added に -Δ_orig が加算されない）**、mute
- _shifted_mux_args / _shifted_mux_args3: itsoffset の割当、avoid_negative_ts、use_editlist、chapters、Δ=0 で従来引数
- clamp_added_start / added_head_skip_us の境界
- build_mix_args: adelay / atrim+asetpts / amix(normalize=0,duration=longest)
### 6.2 E2E（実機 ffmpeg）
1. 音声パケットのビット一致（original/added/bothTracks。added は head_skip 後の切出し区間と比較）
2. **elst（media_time）＋パケット PTS** で位置を検証（ffprobe の start_time は elst により 0 に見える場合があるため単独では使わない）
3. 音声のみ × original × Δ（正負、mp4）: 長さ＝区間長、無音区間の位置で移動を確認
4. addedStartMs / head_skip / 長短クランプ
5. bothTracks: 音声2ストリームが別トラックで、元=元と一致・追加=切出し区間と一致
6. **bothTracks で Δ_orig<0 ∧ Δ_add≠0**: 映像基準の相対位置が式どおり（v0.6 のバグの回帰テスト）
7. bothMix: 長さ＝区間長、normalize=0 で音量破綻なし
8. mute: 音声ストリーム無し。音声のみ+mute は 400
9. audioTiming=false: (a) mute=false なら素の無変換と音声 md5 とストリーム構成が一致、(b) mute=true なら音声ストリームが無い（-an）
10. チャプター: **「ケース1 かつ Δ_orig≠0（itsoffset 経路）」および「0.7 経路で Δ_orig≠0」のときだけ無し**。Δ_add のみ非0 はコピー、**bothMix はケース1・Δ_orig≠0 でもコピー**（映像 TS 不変）
11. 異常系: コンテナ非互換 400、追加ソース欠落 404、mode 不正 400
12. addedReencode=true: 追加のみ再エンコード、元音声は md5 一致
13. 音声のみ × added/bothTracks/bothMix × Δ≠0: 0.8b の表どおりに Δ_orig が無視され（警告）、Δ_add のみ適用されること
14. 3パス（負 Δ 含む）の出力長が区間長に一致（許容 ±1 フレーム = 0.9）
15. bothMix の出力長が区間長に一致（duration=longest でも伸びない = 0.9）
16. 境界: addedStart の丸め / head_skip が追加長以上 / 追加が区間より短い（映像あり=末尾無音、音声のみ=出力長が短くなることを実測して記録）
17. コンテナ依存: 音声のみ × Δ<0 が mp4 では成功し、elst を持たないコンテナ（wav/mp3）では 400 になること（E2E 3 は mp4 の正負、ここでは elst 非対応の拒否を担当）
18. Δ=0 の既存経路に -t が付かず、従来の無変換 E2E がビット一致のまま（回帰）
### 6.3 回帰
e2e_lossless / e2e_audio_api / e2e_containers / e2e_edge が全合格。

## 7. 受け入れ基準
1. 6.1〜6.3 全合格。2. audioTiming=false **かつ mute=false** が素の無変換と音声ビット一致（**mute=true は -an で音声が無い**ので対象外）。3. ずらし時に元音声が再エンコードされていない。4. 出力長が区間長と一致（許容 ±1 音声フレーム ≈21ms、映像がある場合はパケット精度。**音声のみ出力で素材が短い場合は短くなることを許容**）。5. 三者レビュー完全Go。

## 8. リスクと対策
| リスク | 対策 |
|---|---|
| 音声のみ Δ<0 の可否 | E2E 検証、不可なら 400 |
| 3入力 mux の elst | E2E で自前解析 |
| amix の音量・長さ | normalize=0 / duration=longest 固定 + E2E |
| 中間パスの二重補正 | 単体で make_zero 禁止を検証 |
| 既存経路の回帰 | Δ=0 / audioTiming=false は既存分岐をそのまま |

2. 区間開始より前に余裕がない場合のみ、従来のコンテナタイムスタンプ表現
  （itsoffset + edit list）にフォールバックし、その旨を警告する（一部の再生アプリでは
   反映されない）。
3. 無音警告の整理: 従来「ずらし量が区間長以上なら無音」と警告していたが、内容方式では
   音声は常に存在するため該当警告を削除した。実際に音声が落ちるのは末端突破時だけで、
   専用の警告（映像のみ書き出し）が出る。
4. ジョブ結果の `audio` に `contentMs: {advance, reachBack, filterMs}`（ms）を追加し、
   適用内容を監査可能にした。
5. 再エンコード経路にもずらしを適用した（従来は無視されていた）。adelay/atrim フィルタで
   焼き付けるため、どの再生アプリでも確実に反映される。コピー予定だった音声は警告のうえ
   再エンコードに切り替える。区間長以上の負のずらしは音声なし＋警告。消音モードでは音声を
   除外し、追加トラックは非対応の警告を出す。
6a. 区間先頭に遡る余裕がない場合の方式を変更した。旧: コンテナのタイムスタンプ（edit list）。
   新: **音声のみ再エンコードして先頭に N ms の無音を焼き込む**（映像は無変換コピーのまま）。
   理由: edit list を無視する再生アプリでは遅延が消え、「書き出したファイルがずれない」という
   症状になった。焼き込みならどのプレイヤーでも反映される。
   実装上の注意: `adelay` を「ソースの開始オフセットを持つカット」に直接かけると、この
   ffmpeg ビルドでは約106ms が失われ、100ms 指定では無音が実質ゼロになった。
   そのため (1) まず開始0でカット → (2) その0起点ファイルに adelay をかける の二段にした
   （実測 +8.8ms の誤差のみ＝素材自身のリード分）。
   なお音声を再エンコードした場合は `lossless: false` / `audioReencoded: true` を返し、
   UI でも「無変換」と表示しない。
6. 内容方式の部屋判定を厳密化した：区間開始だけでなく、ソース音声の開始位置と比較する。
   冒頭区間など音声が存在しない範囲には遡れないため、その場合はタイムスタンプ方式に
   フォールバックし、警告で明示する（無変換のまま「ずらしたつもりで変わらない」状態を作らない）。

## 追補 v0.17（実装完了後の確定事項・0.2 の変更）

1. マイナスずらしの実現方法を変更した。旧: 映像（と非音声ストリーム）を |Δ| 遅らせる。
   新: **音声の切り出し区間を [開始+|Δ|, 終了+|Δ|] にずらす**（音声の内容を |Δ| 進める）。
   理由: 映像は基準トラックであり、プレイヤーが映像開始を 0 に正規化するとずれが消え、
   「書き出したファイルを再生しても同期して見える」という不具合になった。新方式では
   両トラックとも 0 起点のままで、ずらしは内容に乗るため、どのプレイヤーでも保持される。
   無変換（パケットコピー）は維持。素材終端に達する場合は終端でクランプし警告を出す。
   プラスずらし（音声を遅らせる）は従来どおり itsoffset で音声の開始を +Δ にする。
   （v0.18 で内容方式に変更。余裕がない場合のみ itsoffset にフォールバック）
2. 追加トラックのオフセットは映像項に追従する。映像が動かなくなったため、実質 max(0, Δ_add)
   （負の追加ずらしは従来どおりヘッドスキップで吸収）。
3. 計画の空判定に audioSkipUs を含める（含めていなかったためマイナスずらしの計画が
   丸ごと破棄され、無変換の素の出力になっていた）。
4. デバッグログ data/logs/export_debug.log（JSON Lines、7日保持）を追加。計画・経路・
   書き出し後の実測（ストリーム開始時刻・コーデック・edit list）を記録する。
