# シークバー／トリミングバーの誤操作対策（計画 v0.1）

作成: 2026-11-06 / 対象: TrimStudio（web-qwen/index.html）

## 1. 症状（ユーザー報告）

- シークバー（再生位置）とトリミング位置決めバー（IN / OUT）が**毎回誤操作**になり、
  **動かすつもりのない方**を動かしてしまう。

## 2. 現状の実装（原因の特定）

1本の 46px の帯に、キーフレーム目盛り・切出範囲・**IN ハンドル**・**OUT ハンドル**・**再生ヘッド**が同居しています。

```
<div class="timeline" id="timeline">      // 高さ 46px / touch-action:none
  <div class="region" id="region"></div> // 切出範囲
  <div class="handle in"  id="hIn"></div>   // 幅 16px（見た目のグリップは 4x26px）
  <div class="handle out" id="hOut"></div>  // 幅 16px
  <div class="playhead" id="playhead"></div> // 幅 2px ＋ 12px のひし形
</div>
```

```
timeline.pointerdown:
  e.target が #hIn / #hOut と「完全一致」したときだけ IN / OUT ドラッグ
  それ以外はすべて drag = "seek"（＝再生ヘッドが動く）
  しかも pointerdown の瞬間に tlMove() を呼ぶ（触っただけで動く）
```

### 誤操作が起きる理由（根本原因）

| # | 原因 | 影響 |
|---|---|---|
| R1 | **ハンドルの当たり判定が 16px 幅**。指の接触は約 40〜44px なので、狙っても数px外すと当たらない | 狙った IN/OUT が動かない |
| R2 | **当たらなかった押下はすべて「シーク」になる**（既定動作が seek） | ついでに再生ヘッドまで動く＝「違う方を動かした」 |
| R3 | **押した瞬間に動き始める**（デッドゾーンが無い） | 触れただけ・スクロールのつもりで位置が変わる |
| R4 | 当たり判定が `e.target` 依存で、**重なりや近接時の優先規則が無い** | IN と再生ヘッドが近いと狙いが定まらない |
| R5 | **取り消し（Undo）が無い** | 誤操作したら手で戻すしかない |
| R6 | ハンドルがバー両端いっぱいにあり、**画面端のジェスチャと競合**しやすい | 端で誤動作 |
| R7 | 掴んでいる対象の**表示が変わらない**（選択中かどうか分からない） | 誤操作に気づくのが遅れる |

## 3. 対策（案）

### A. 上下2段に分離する（最重要・構造で解決）
- **上段＝トリミングバー**: IN / OUT ハンドルと切出範囲のみ。**ここではシークしない**。
- **下段＝シークバー**: 再生ヘッドのみ（高さ 28〜32px）。**ここでは IN / OUT を動かさない**。
- 効果: 誤って掴んでも「別の種類の操作」にならない。R1〜R4 が構造的に消える。

### B. 当たり判定を指のサイズに広げ、最近傍で決める
- `e.target` を見ず、**押下座標**から IN / OUT の中心までの距離で判定（しきい値 ±22px＝44px 幅）。
- 上段: しきい値内ならそのハンドル、外なら「範囲移動（両方）または何もしない」。
- 下段: 常にシーク。
- 効果: R1, R4 を解消。

### C. デッドゾーン（触っただけでは動かさない）
- pointerdown では**選択だけ**。**8px 以上動いたら**ドラッグ開始。
- 動かさず離したとき: 上段＝ハンドル選択のみ／下段＝その位置へシーク（タップ相当）。
- 効果: R3 を解消。

### D. 操作中の明確なフィードバック
- 掴んだ対象を強調（色・太さ・拡大）、上部に**時刻の吹き出し**、テキストで「IN を 00:12.345 に移動中」。
- Android は `navigator.vibrate(10)` で触覚フィードバック。
- 効果: R7 を解消し、誤操作にすぐ気づける。

### E. 元に戻す（Undo / Redo）
- IN / OUT / 再生位置の変更を最大10件保持し、「元に戻す」ボタンを常設。
- 効果: R5 を解消。誤操作の実害を1タップで取り消せる。

### F. 動画側でもシークできるようにする
- 映像を左右にドラッグ＝スクラブ（シーク）。タイムラインを使わない経路を増やす。
- 効果: 混雑した帯に触る回数を減らす。

### G. ドラッグ不要の導線を目立たせる
- 既存の「現在位置に設定」（IN / OUT）と ±1F ボタンで、**シーク→ボタン**だけで決められる。
- この2つを主要導線として見た目を強調（枠色・大きさ）。
- 効果: そもそもドラッグしない操作を促す。

### H. IN/OUT ロック
- トグルで「IN/OUT を固定」。ON の間は上下どちらでもシークのみ可能。
- 効果: 範囲が決まった後の誤操作を完全に防ぐ。

### I. 端の余白
- バー左右に 10px の内側余白を設け、端のハンドルを画面端から離す。
- 効果: R6 を解消。

### J. スナップ
- IN / OUT はキーフレームへスナップ（既定）。長押しで精密モード（スナップ解除）。
- 現在のスナップ状態をハンドル付近に表示。
- 効果: 位置の「ずれ」を減らす（誤操作そのものではないが体感が良くなる）。

## 4. 推奨パッケージ

| 区分 | 採用 |
|---|---|
| 必須（誤操作の根本対策） | **A（2段化）＋ B（44px・最近傍）＋ C（デッドゾーン）＋ D（フィードバック）＋ E（Undo）＋ I（端余白）** |
| 推奨 | F（動画スクラブ）、G（ボタン導線の強調）、H（ロック） |
| 任意 | J（スナップ表示）、触覚 |

### 画面イメージ（2段化）

```
┌───────────────────────────────────────────┐
│ 00:12.345                    05:15:38.333 │  ← 現在 / 全体の時刻
├───────────────────────────────────────────┤
│ ▉IN                                     OUT▉│  ← 上段: トリミングバー（IN/OUT のみ）
│ ░░░░░░░░░░░░切出範囲░░░░░░░░░░░░░░░░░░░░░░░ │     ここではシークしない
├───────────────────────────────────────────┤
│        │                                  │  ← 下段: シークバー（再生ヘッドのみ）
└───────────────────────────────────────────┘     ここでは IN/OUT を動かさない
```

## 5. 受入基準

1. 下段（シークバー）を操作しても **IN / OUT が変化しない**（値が変わったら失敗）。
2. 上段で狙ったハンドルから **±15px ずれた押下**でも、**狙った方**が動く（誤操作 0 件）。
3. 押しただけで動かない（8px 未満の移動では値が変わらない）。
4. ドラッグ中は対象が強調され、時刻が表示される。
5. 「元に戻す」で直前の変更（IN / OUT / 再生位置）が戻る。
6. 既存機能の回帰なし（書き出し・キーフレーム目盛り・IN/OUT ボタン・時間入力）。

## 6. テスト計画

- **論理の単体テスト（Node）**: 判定を純関数 `pickTimelineTarget(x, width, inX, outX, row)` に切り出し、
  「狙いから ±15px ずれても正しい対象が返る」「下段では常に seek」「上段のしきい値外では seek にならない」を検証。
- **静的ガード**: 2段構成（trim bar / seek bar）、44px 判定、デッドゾーン、Undo の存在を check_ui_static に追加。
- **スモーク**: 既存の tests/smoke_qwen_js.js でトップレベル実行エラーが無いこと。
- **実機**: スマホで実際に IN / OUT と再生位置を操作し、誤操作が起きないことを確認（ユーザー）。

## 7. リスク・ロールバック

- 2段化で縦の占有が増える（約 30px）。プレビュー領域が少し狭くなるが、誤操作の解消を優先。
- 変更は web-qwen/index.html（＋必要なら web/app.js）に閉じる。CSS とポインタ処理のみで、書き出しロジックには触れない。
- ロールバックはファイル単位で可能。

## 8. 実装順序（見積り）

1. 判定関数の切り出しと単体テスト（0.5h）
2. 2段化のマークアップ・CSS（0.5h）
3. ポインタ処理（デッドゾーン・最近傍・フィードバック）（1h）
4. Undo / Redo（0.5h）
5. ボタン導線の強調・ロック・端余白（0.5h）
6. 静的ガード・スモーク・回帰・レビュー 2 巡（1.5h）

# 追補 v0.2（第36ラウンドのレビュー指摘を反映）

レビューで「重大3・中4・軽2」の指摘を受けたため、判定規則・Undo の粒度・デッドゾーンの意味を確定します。

## 1. 判定規則の確定（重大1・中4・中5）

### レイアウト（2段・当たり判定が重ならない）
| 段 | 高さ | 担当 |
|---|---|---|
| 上段（トリミングバー） | 44px | IN / OUT ハンドル、切出範囲、キーフレーム目盛り |
| 隙間 | 6px | なし（どちらの段にも反応しない） |
| 下段（シークバー） | 30px | 再生ヘッドのみ |

- 2つの段は**別々の DOM 要素**にし、それぞれが自分の pointerdown を受ける。**上下の当たり判定は重ならない**（隙間は無反応）。
- 当たり判定の 44px は**横方向のみ**に適用する（縦は段の高さ）。バーの内側からはみ出さない（端は 10px の内側余白でクランプ）。
- 上段の合計は 44 + 6 + 30 = 80px（現状 46px から +34px）。

### 対象の決め方（純関数）
@@
pickTimelineTarget(x, width, inX, outX, row, lastHandle) -> "in" | "out" | "seek" | "range"
@@
- 下段（row = "seek"）: 常に "seek"。**IN / OUT は絶対に動かない**。
- 上段（row = "trim"）:
  1. IN 中心までの距離 dIn、OUT 中心までの距離 dOut を計算。
  2. 両方とも 22px を超える → "range"（切出範囲の平行移動。移動量が 8px を超えたら両方を動かす。タップなら何もしない）。
  3. 片方だけ 22px 以内 → そのハンドル。
  4. **両方とも 22px 以内（IN と OUT が 44px 未満に近接）** → 次の優先順で決める:
     a. @@lastHandle@@（直前に動かした／選択したハンドル）が候補内なら、それ（**スティッキー**）。
     b. 候補が無ければ距離が近い方。差が 8px 未満で決められないときは @@lastHandle@@、それも無ければ OUT（右側）。
- 受入基準(2)の再定義: **IN と OUT が 44px 以上離れている場合**、狙いから ±15px ずれても狙った方が動く。近接時は「直前に選んだ方が動く」（スティッキー）を検証する。

### IN / OUT の交差（中5）
- **クランプ方式**を採用し、入れ替え（スワップ）はしない。
- IN を OUT より右へ動かそうとすると OUT の位置で止まり、ハンドルが軽く振動（または色が変わる）して「これ以上動かせない」ことを示す。
- 数値入力で IN > OUT になった場合も同じくクランプする。

## 2. Undo の粒度（重大2）

- **1回のドラッグ＝1エントリ**。pointerdown 時に「操作前の状態」を記録し、pointerup 時に**値が変わっていたときだけ**履歴へ確定する（pointermove ごとには積まない）。
- 連続タップやボタン操作（現在位置に設定 / ±1F）も 1 操作＝1エントリ。同一対象の 1 秒以内の連続変更はまとめて 1 エントリに統合する。
- 履歴は最大 20 件。UI には「元に戻す（IN を戻す）」のように**何が戻るか**を表示する。
- 受入基準(5)の再定義: **ドラッグ1回につき1回の「元に戻す」で操作前の値に戻る**（10 回ドラッグしても 10 回で全部戻せる）。

## 3. デッドゾーンとタップの分離（重大3）

- デッドゾーンは**ドラッグの判定**にのみ使う（8px）。
- 上段: 8px 未満で離した場合は **IN/OUT の値を変えない**（ハンドルの選択のみ）。
- 下段: 8px 未満で離した場合は**タップとしてその位置へシーク**する（デッドゾーンの対象外）。
- 判定は純関数 @@resolveDrag(movedPx, elapsedMs) -> "drag" | "tap"@@ に切り出す（しきい値の単体テスト用）。
- 受入基準(3)の再定義: **上段では 8px 未満の移動で IN / OUT の値が変わらない**（下段のタップシークは対象外）。

## 4. 選択状態の意味（中7）

- 上段のハンドルをタップすると**選択状態**になる（強調表示＋「IN 選択中」）。
- 選択中は、**±1F / ±1s / ±キーフレーム と「現在位置に設定」が選択中のハンドルに作用する**（ドラッグ不要の確定操作。G と一体）。
- 選択中にもう一度タップ、または上段の余白をタップすると選択解除。
- 何も選択していないときの「現在位置に設定」は従来どおり押したボタン（IN / OUT）に作用する。

## 5. 必須項目から触覚を外す（中6）

- 必須 D = **掴んだ対象の強調＋時刻の吹き出し＋テキスト表示**。
- 触覚（navigator.vibrate）は**任意 K** に移す（端末依存で失敗しても動作に影響させない）。

## 6. 端の余白と当たり判定（軽8）

- バーの左右に 10px の内側余白を置き、端のハンドルでも判定領域がバーの外へはみ出さないようにする。
- これで画面端のジェスチャ（戻る/スワイプ）と競合しにくくする。**実機での確認項目**とする（文面では検証不能）。

## 7. テスト計画の精密化（軽9）

- **純関数の単体テスト（Node）**:
  - @@pickTimelineTarget@@: 下段は常に seek／上段の ±15px ずれ／近接時のスティッキー／両方遠い場合は range。
  - @@resolveDrag@@: 8px 未満＝tap、8px 以上＝drag。
  - Undo 集約: 連続 move では 1 エントリ、確定は pointerup で 1 回。
- **静的ガードは構造のみ**（2段の要素が存在する、関数が読み込まれている等）。レイアウト依存の検証は静的チェックに依存せず、実機チェックリストで行う。
- **実機チェックリスト**（ユーザー実施）: 下段で IN/OUT が動かない／上段で狙った方が動く／タップだけで値が変わらない／Undo が 1 回で戻る／画面端で誤爆しない。
- ブラウザ自動化（Playwright 等）が使える環境になったら、境界の実測テスト（getBoundingClientRect）を追加する。

# 追補 v0.3（第37ラウンドのレビュー指摘を反映）

v0.2 へのレビューで「重大2・中3・軽3」の指摘を受けたため、Undo の粒度とスティッキー判定の状態遷移を確定します。

## 1. Undo の粒度を一本化（重大R1）

- **時間による統合は行わない**（「1秒以内は統合」を削除）。
- **1回の操作＝1エントリ**。操作の種類は次の3つで、いずれも「開始時に操作前の値を記録し、終了時に値が変わっていれば確定」する:
  1. ドラッグ（pointerdown → pointerup）
  2. タップ選択後のボタン操作（現在位置に設定 / ±1F / ±1s / ±KF）
  3. 時間の直接入力（change 確定時）
- pointermove では履歴に積まない。したがって**10 回ドラッグすれば 10 回の「元に戻す」で全部戻せる**（受入基準(5)がそのまま成立）。
- 履歴は最大 20 件。ボタンは「元に戻す（IN を戻す）」のように**何が戻るか**を表示する。

## 2. lastHandle（直前に触ったハンドル）の状態遷移（重大R2）

@@
lastHandle は、IN と OUT が 44px 未満に近接したときの「どちらを動かすか」を決めるためだけに使う。
@@

| 出来事 | lastHandle の扱い |
|---|---|
| 上段で IN / OUT をタップ・ドラッグ開始した | **そのハンドルに更新**（ドラッグ終了後も保持する） |
| 上段の余白（range 領域）をタップした | **クリア**（選択解除） |
| 選択中のハンドルをもう一度タップした | **クリア**（選択解除） |
| 下段（シークバー）を操作した | **変更しない**（IN/OUT の選択は維持） |
| 「元に戻す」「やり直す」を実行した | **クリア**（戻した後の誤爆を防ぐ） |
| ソースを切り替えた / 動画を開き直した | **クリア** |
| ページを再読み込みした | **クリア**（localStorage には保存しない） |

- これにより「意図を変えたのに古いハンドルが動き続ける」状態は、余白タップ・再タップ・Undo・ソース切替で必ず解消される。

## 3. 判定規則の整理（重大R2補足・軽L1・軽L3）

@@
dIn = |x - inX|, dOut = |x - outX|   （22px = 44px 当たり判定の半径）
@@

| 条件 | 結果 |
|---|---|
| row = "seek"（下段） | "seek"（IN/OUT は絶対に動かない） |
| dIn > 22 かつ dOut > 22 | "range"（切出範囲の平行移動） |
| dIn <= 22 かつ dOut > 22 | "in" |
| dOut <= 22 かつ dIn > 22 | "out" |
| 両方 <= 22（近接） | lastHandle があればそれ／無ければ近い方／差が 8px 未満なら OUT |

- これで v0.2 の到達不能な分岐（lastHandle を二度使う記述）を解消。
- **±15px は仕様値ではなくテストの許容誤差**（指のずれを模擬する値）。仕様値は 22px（44px の当たり判定）。

## 4. range（平行移動）の確定（中M1・中M3）

- 範囲は**長さを保った剛体**として動かす。移動量は「IN が 0 以上」「OUT が全体長以下」を満たす範囲にクランプし、**端に達したら長さを保ったまま止まる**（IN/OUT は交差しない）。
- IN と OUT の間隔が 44px 未満のときは、ハンドルの当たり判定が重なるため range 移動は成立しない（**仕様として明記**。この場合はスティッキーでハンドルを動かす）。

## 5. range 領域のタップ（中M2）

- 上段の range 領域を 8px 未満でタップした場合は、**何も動かさず選択解除のみ**（シークもしない）。
- シークは下段（シークバー）と映像のドラッグ（F）で行う。

## 6. resolveDrag の簡素化（軽L2）

@@
resolveDrag(movedPx) -> "drag" | "tap"     # 8px 未満は tap
@@

- elapsedMs は使わない（しきい値は移動量のみ）。将来ダブルタップ機能を作るときに再検討する。

## 7. 受入基準 v0.3（確定）

1. 下段の操作で IN / OUT が変化しない。
2. 上段で IN/OUT が 44px 以上離れているとき、狙いから**±15px ずれても狙った方**が動く。近接時は**直前に触った方**（lastHandle）が動く。
3. 上段では 8px 未満の移動で IN / OUT の値が変わらない（下段のタップシークは対象外）。
4. ドラッグ中は対象が強調され、時刻が表示される。
5. **ドラッグ1回につき「元に戻す」1回で操作前の値に戻る**（時間による統合は行わない）。
6. 既存機能の回帰なし（書き出し・キーフレーム目盛り・IN/OUT ボタン・時間入力・プロキシ）。

# 追補 v0.4（第38ラウンドのレビュー指摘を反映）

v0.3 へのレビューで「重大1・中1・軽3」の指摘を受けたため、判定表の前提条件と、選択が無いときのボタン挙動を確定します。

## 1. 判定表に「範囲の長さ」の前提を追加（重大S1）

@@
gap = outX - inX（ピクセル）   range は gap >= 44 のときだけ成立する
@@

| 条件 | 結果 |
|---|---|
| row = "seek"（下段） | "seek" |
| **gap < 44** かつ 両方とも 22px 超 | **"none"**（何もしない。選択解除のみ） |
| gap >= 44 かつ dIn > 22 かつ dOut > 22 | "range" |
| dIn <= 22 かつ dOut > 22 | "in" |
| dOut <= 22 かつ dIn > 22 | "out" |
| 両方 <= 22 | lastHandle → 近い方 → 差 8px 未満なら OUT |

- 「間隔が 44px 未満のときにハンドルから遠い場所を触った」場合は **"none"**（値も選択も変えない）。これで M3（近接時は range が成立しない）と矛盾しない。
- 単体テストに **gap<44 で dIn>22 かつ dOut>22 → "none"** のケースを必ず入れる。

## 2. 選択が無いときのボタン・入力の対象（中M1）

@@
「選択」はステップ操作の対象を決めるためだけに使う。それ以外の操作は「ボタンや入力欄そのもの」が対象を決める。
@@

| 操作 | 対象 |
|---|---|
| ±1F / ±1s / ±KF（ステップ） | **選択中のハンドルがあればそれ**。選択が無ければ**再生ヘッド（現在位置）**（＝現状と同じ挙動） |
| 「現在位置に設定」（IN 用 / OUT 用） | **そのボタン自身のハンドル**（IN ボタン→IN、OUT ボタン→OUT）。選択状態に依存しない |
| IN / OUT の時間入力欄 | **その入力欄自身**（IN 欄→IN、OUT 欄→OUT） |
| 上段のハンドルをドラッグ | 掴んだハンドル（同時に選択される） |

- これで lastHandle がクリアされていても、すべての操作の対象が一意に決まる。
- 選択中はステップボタンの近くに「IN を微調整中」と表示し、対象が再生ヘッドでないことを明示する。

## 3. pointercancel の扱い（軽L-A）

- **破棄する**。操作前の値に戻し、履歴にも積まない（着信・システムジェスチャ等の中断で勝手に確定しない）。
- pointerup と同じ確定処理を通るのは pointerup のみ。pointercancel / lostpointercapture は破棄。

## 4. range 移動の Undo 表示（軽L-B）

- range（切出範囲の平行移動）は **IN と OUT をまとめて 1 エントリ**で戻す。
- ボタンのラベルは「元に戻す（切出範囲を戻す）」のように表示する（IN 単体なら「元に戻す（IN を戻す）」）。

## 5. Redo スタック（軽L-C）

- Undo で取り出したエントリは Redo スタックへ移す。**新しい操作を行うと Redo スタックはクリア**する。
- 上限 20 件は **Undo + Redo の合計**で数える（どちらかに入っていれば 1 件）。
- 「やり直す」は Redo スタックの先頭を適用する。

## 6. ハンドルのクランプ（再掲・未確認指摘の解消）

- IN のドラッグは **OUT の位置でクランプ**（IN <= OUT）。OUT のドラッグは **IN の位置でクランプ**（OUT >= IN）。入れ替え（スワップ）はしない。
- range の平行移動は長さを保ち、IN は 0 以上、OUT は全体長以下でクランプする。端では長さを保ったまま停止する。

## 7. 受入基準 v0.4（確定）

1. 下段の操作で IN / OUT が変化しない。
2. IN/OUT が 44px 以上離れているとき、狙いから ±15px ずれても狙った方が動く。近接時（44px 未満）は**直前に触った方**（lastHandle）が動く。
3. 上段では 8px 未満の移動で IN / OUT の値が変わらない（下段のタップシークは対象外）。間隔 44px 未満でハンドルから遠い場所をタップしても何も変わらない（"none"）。
4. ドラッグ中は対象が強調され、時刻が表示される。
5. ドラッグ1回につき「元に戻す」1回で操作前の値に戻る（range は IN/OUT をまとめて 1 回）。
6. 選択が無いときのステップ操作は再生ヘッドを動かす（従来挙動）。「現在位置に設定」と時間入力はそれぞれの対象に作用する。
7. 既存機能の回帰なし（書き出し・キーフレーム目盛り・IN/OUT ボタン・時間入力・プロキシ）。

## 8. 単体テストの必須ケース（確定）

- pickTimelineTarget: 下段＝常に seek／±15px ずれ＝正しいハンドル／gap>=44 で両方22px超＝range／**gap<44 で両方22px超＝none**／近接＝lastHandle 優先／lastHandle 無しで差8px未満＝OUT。
- resolveDrag: 7px＝tap、8px＝drag、20px＝drag。
- Undo: ドラッグ1回＝1エントリ／pointercancel＝エントリ無し／range＝IN/OUT まとめて1エントリ／新規操作で Redo クリア。

# 追補 v0.4.1（第39ラウンドの軽微指摘を反映・両レビュアー完全Go）

1. **近接時のタイブレークを表に明記**（軽1）: 判定表の「両方 <= 22」の行は
   「lastHandle があればそれ → 無ければ距離が近い方 → **差が 8px 未満で決められない場合は OUT**」。
   この 8px はステップ操作の対象を決める 8px とは**別の規則**（近接タイブレーク専用）。
2. **履歴上限の破棄規則**（軽2）: Undo + Redo が 20 件を超えたら、**最も古いエントリから破棄**する。
3. **「回帰なし」の範囲**（軽3）: 次のスイートをすべて通すことを受入条件(7)の範囲とする。
   - tests/test_unit.py
   - tests/e2e_lossless.py（無変換: offset=0 / 165/167 / interior_bad=0 / デコードエラー0）
   - tests/e2e_edge.py / tests/e2e_metadata.py / tests/e2e_download.py / tests/e2e_fsops.py / tests/e2e_export_ops.py
   - tests/check_ui_static.py（静的ガード）
   - tests/smoke_qwen_js.js（インライン script の実行時エラー検出）
4. **"none" の文言統一**（Flash 指摘）: 「何も操作しない（選択も値も維持）」に統一する（v0.4 の表の「選択解除のみ」はこの意味に読み替える）。
5. **選択中表示**: IN 選択時は「IN を微調整中」、OUT 選択時は「OUT を微調整中」と表示する。
6. **距離の定義**: dIn / dOut は**ハンドル中心からの距離（px）**とする。
