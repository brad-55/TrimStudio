# 追加音声ずらしの実メディア・マトリクステスト計画（第11版）

## 目的

実在の h264 / HEVC 動画（実音声）で、元音声・追加音声の正負のずらしが、書き出しとプレビュー
（焼き込みプロキシ）の両方で「目的どおり」に反映されることを独立に検証する。

## 素材

| 役割 | ファイル | コーデック | 長さ | 音声 |
|---|---|---|---|---|
| h264 側 | `L:\dev\VID_20261103_114920_003.trim-…-00h06m45s269.mp4` | h264 3840x2160 | 405.269s | AAC 48kHz stereo |
| HEVC 側 | `L:\dev\ScreenRecording_05-25-2026 19-41-41_1_…_再エンコード_H265-NVENC_20261110-2358.mp4` | hevc 2556x1180 | 18.900s | AAC 44.1kHz stereo |

## パイロット校正（実装前）

1. 選定区間 [2.0,6.0) の元・追加音声の RMS を測り、**-40dBFS 未満または無音が大半なら区間を
   [5.0,9.0) 等へ変更**して計画に記録する（相関オラクルの前提確保）。
2. **md5 オラクルの事前検証**: 1役割ずつ、original -500 / original +500 / bothTracks -500 の書き出しを
   先に流し、出力側シークで作った期待パケット列と md5 が一致することを確認する。不一致なら
   「期待区間をパケット境界へスナップする規則（`-ss` 出力側シークの最初のパケット以上、半開区間）」を
   実測して計画に記録し、その規則でオラクルを実装する。**区間を変更した場合は台帳を再生成し、
   変更後の値をレビュー証跡として再添付する。**
3. 2役割 × bothMix × 書き出し/プレビュー の 4 ケースを先に流し、期待波形との正規化相関の実測値を
   記録。**相関閾値 = min(0.85, 実測最小 - 0.1)**、ただし **0.75 を下限**（それ未満なら区間・
   オラクル設計を見直す）。識別性マージン 0.15 は固定で緩めない。

## ケース行列

### ベースライン 0ms（20）
ずらし0 × モード5（original/added/bothTracks/bothMix/mute）× 役割2 × 出力先2。
ずれが無いこと（PTS 0・内容一致・相関ピーク0・mute は音声なし）を確認。

### 基本 4 × 2 × 5 × 2 = 80

ずらし4通り（`(元Shift, 追加Shift)` の4組）:
`(-500,-500)` / `(+500,+500)` / `(-500,+500)` / `(+500,-500)`。
× 役割2 × モード5 × **出力先2（書き出し / プレビュー）** = 80。

#### 書き出し（切り出し区間 4 秒）

| モード | 期待 |
|---|---|
| original | 元音声のみ。元 -500→内容 [2.5,6.5)、元 +500→内容 [1.5,5.5)（遡る余裕あり）。追加のずらしは**警告なしで無視**（追加ソース未指定） |
| added | 追加音声のみ。追加 -500→A[0.5,4.5) を内容で前進、+500→A[0,4) をコンテナ timestamp（開始 PTS 0.5）。元のずらしは**警告**して無視 |
| bothTracks | 2トラック。track0=original と同じ、track1=added と同じ |
| bothMix | 1トラックにミックス（元=フィルタ、追加=フィルタ）。元+は adelay（区間先頭から内容）、元-は atrim(0.5s) により出力 t=0 から 0.5s 前進した内容（例 [2.5,6.5)）を再生（先頭無音なし）、追加+は adelay、追加-は atrim。要再エンコード（警告あり） |
| mute | 音声ストリームなし。両ずらしは**警告**して無視 |

#### プレビュー（全長・trim 非対応・アンカー0）

| モード | 期待（プロキシ長 = 元ソース長） |
|---|---|
| original | -500→元音声を atrim(0.5s) して先頭から（=source[0.5,end)）、+500→先頭 0.5s 無音＋source[0, dur-0.5)（末尾 0.5s は切れる） |
| added | -500→追加音声を atrim(0.5s) して先頭から（=A[0.5,end)。プロキシ長に満たない末尾は無音パディング）、+500→先頭 0.5s 無音＋A[0, …]（プロキシ長まで、追加が短ければ残りは無音、長ければ切れる）。切れ目はサンプル境界で比較し、末尾の部分パケットは評価しない（先頭 min(実際,期待) サンプルのみ相関） |
| bothTracks | **プレビューは常に1トラックに焼き込む**ため bothMix と同じ期待（元成分＋追加成分のミックス）。音声ストリーム数は1 |
| bothMix | 同上（元成分＋追加成分のミックス） |
| mute | 音声ストリームなし |

- プレビューに切り出し区間の指定はない（既存仕様）。期待波形はプレビュー長に合わせて構築する。

## 追加ケース

1. **0ms 対照（20）**: 上記ベースライン。
2. **addedReencode=true（4・書き出しのみ）**: added モードで -500/+500 を各役割1回。追加音声は
   再エンコードされるが、**配置は従来どおり mux の -itsoffset（コンテナ timestamp）**で行われる実装
   （`_added_cut_args` で音声を再エンコード → `_shifted_mux_args` の added オフセット）。
   したがって +500 は **PTS 0.5 を期待**し、内容は再エンコードのため md5 ではなく相関で検証する。
   相関は**コンテナ timestamp を除外してデコードした音声**で行う（手順: 出力を `ffmpeg -i out -map 0:a
   -f f32le -` でデコードし、先頭パケットから始まるサンプル列を使う。`-copyts` や start_time の
   再配置はしない）。そのため期待波形の delaySec は 0.0 とする（PTS は別オラクルで検証）。
   メタデータ: 現実装では `lossless=true`・`audioReencoded=false` のまま（added 側の再エンコードを
   フラグに反映しない既知の報告不整合）。本テストは警告「追加音声のみ再エンコード」と実出力
   （再エンコードされていること）を検証し、フラグの不整合は**別途修正候補**として記録する。
3. **delayNoReencode（2・書き出しのみ）**: audioMode=original・追加なし・IN=0/OUT=4s・+500ms（この経路は contentMs が空 {}・appliedMs 0/0/0）・
   delayNoReencode=true・mp4。delayMode="timestamp"・lossless=true・開始 PTS 0.5・音声パケット = 元[0,4)。
4. **フル素材健全性（4）**: 上記。

合計 **110 ケース**（80+20+4+2+4）。**全110ケースの台帳を `review/_matrix_ledger.txt` として添付（ID一意・variant付き・プレビュー bothTracks は streams=1・フル素材は duration=405.269/18.9）**
（id 規則: `{target}-{role}-{mode}-{±orig}_{±added}`、role は h264=元h264/追加HEVC、hevc=元HEVC/追加h264。
台帳の `src`/`add`/`full` はそれぞれ「元素材（抜粋）」「追加素材」「元ファイルそのもの」を指す）。

## 独立オラクル

1. **パケット md5（コピー経路）**: 対象ストリームを ADTS 再フレームしてバイト一致。期待区間は実装と
   同じ**出力側シーク**（`-ss` を入力の後）でソースから作る。±500ms は AAC フレーム長の整数倍では
   ないが、既存 E2E で 2000ms でも一致実績あり。半開区間・境界はパケット数一致で担保。
   負シフトは「ずらしていない区間」と md5 が**異なる**ことも確認（識別性）。
2. **コンテナ timestamp（追加 +500）**: (a) ffprobe 音声 `start_time ≈ 0.5`（実測 0.5 確認済み）
   **または** (b) elst media_time が 0.5s 遅延を示す。加えて内容パケット = A[0,4)。
3. **波形相互相関**（プレビューの期待成分は **遅延/トリム後の有効長 = min(素材長-トリム, プロキシ長-遅延)** だけ作り、ミックス期待はプロキシ長まで無音パディング。成分別相関は有効長の区間で評価）:
   - **単一成分モード（original, added）**: その成分のみ。期待波形（mono 48k、プレビューは全長）との
     正規化相関 **≥ 確定閾値（0.75〜0.85。パイロット校正で確定）**、ピーク位置 ±60ms。
   - **ミックスモード（bothMix, プレビュー bothTracks）**: 元成分＋追加成分を 48k で加算した期待波形との
     相関 **≥ 確定閾値（0.75〜0.85。パイロット校正で確定）**、±60ms。加えて**成分別相関**: 実出力と各期待成分（元成分・追加成分）の正規化相互相関のピークを個別に測る。
期待成分のエネルギー E1・E2 から理論上限 sqrt(Ei/(E1+E2)) を計算し、**その 0.7 倍を下限**
（最低 0.35）とする（音量差が大きい実素材でも偽陰性にしない動的しきい値。単純な正規化相互相関で定義）。
     さらに**誤ったずらし**として (a) 0ms 期待波形 と (b) 符号反転した期待波形 の両方を作り、
真の期待波形との相関ピークが両方より **0.15 以上高い**（識別性）。
4. **ストリーム有無（mute）**: 音声ストリームが存在しない。プレビューも同様。
5. **メタデータ（書き出しのみ・モード別表）**:

| モード | warnings（既知部分文字列の完全一致） | appliedMs video/audio/added | contentMs | delayMode（代表値） |
|---|---|---|---|---|
| original | なし（added=None のため追加ずらしは無視） | 0 / 0 / 0 | -500: advance=500 / +500: reachBack=500 | -500: none / +500: content |
| added | 「追加のみモードでは元音声のずらし」 | +: 0/0/500, -: 0/0/0 | 0/0/0 | +: timestamp / -: none |
| bothTracks | なし | 0 / 0 / +:500 (負:0) | 元シフト: -500 advance=500 / +500 reachBack=500 | **単一値は元トラックのみ**を表す: +500 content / -500 none。追加 +500 の timestamp は `appliedMs.added=500` と track1 の PTS 0.5 で別途検証 |
| bothMix | 「音声をミックスするため音声のみ再エンコード」 | +: 0/500/500, 負: 0/0/0（符号ごとに audio=max(0,元), added=max(0,追加)） | filterMs=0（lossless ミックス経路は reencodeFilterShiftMs を使わない） | **元トラックの offset 由来**: 元+なら timestamp / 元-なら none（追加の符号は delayMode に影響しない）。実装はフィルタ経路だが delayMode は offsets 由来（不一致なら実バグとして扱う） |
| mute | 「消音ではずらしを無視」 | 0/0/0 | 0 | none |
   ※ bothMix の `lossless`/`audioReencoded` は現実装の報告値（再エンコードしているが
   filterMs に記録されない）をパイロットで実測し、期待値を固定する。意図と異なる場合は実バグとして
   レビューで扱う（このテストで検出対象）。
6. **映像不変と A/V 整合**（duration 比較は **±2ms の許容誤差**）: 映像 codec・解像度一致。映像パケット数 = 元区間 +0〜+2。実測（既存 E2E, mp4/h264 4s 区間）で 120→122 の +2 が
   出たのは、カット境界のフレーム包含と mp4 再マルチプレックス時の先頭/末尾パケットの丸めによる。
   負方向（欠落）は不可、+3 以上も不可とする。映像 duration（区間長 4s）と音声 **stream duration**（start_time を除く長さ）の差 ±25ms 以内
（timestamp 遅延ケースでも開始位置は start_time 側で検証し、長さ比較には混ぜない）。
   プレビューは h264 元=映像コピー / HEVC 元=プロキシ動画であることと解像度を記録・比較。

## 実行方法・成果物

- `tests/e2e_audio_matrix.py`（`python tests/e2e_audio_matrix.py [BASE]`）を新規作成。
  110 ケースを実行し OK/FAIL と理由を出力、最後に `RESULT: OK` / `FAIL(n)`。
  ファイルは `data/test/matrix/`（gitignore 領域）。**全110ケースの台帳 JSON** を保存する。
  台帳の各要素は `{id, target, role, mode, shiftOrig, shiftAdded, addedStartMs, source, added,
  expected:{status, audioStreams, oracles:[...], packetMd5:[...], metadata:{...}, corr:{...}}}` とし、
  複数オラクルは `oracles` 配列で表現する。
  レビューには台帳の全件（入力パラメータ＋期待値参照）を添付する。FAIL 詳細も保存する。
- 実サーバー（8013）で実行し、`/api/health` の build が作業ツリーと一致してから開始。
- 実行ログ（UTF-8）を `review/_matrix_*.log` に保存しレビュー証跡とする。プレビュー API は
  warnings を返さないため、プレビュー mute ケースでは warnings 検証を行わない（no_audio のみ）。
- 台帳の `oracles` に warnings 指定がないケースは「警告なし」をアサートする（解釈規則）。
- フル素材の 300s 待機がタイムアウトし再試行で成功した場合は「RETRY-OK」としてログに記録し、
  最終集計では PASS とする（FAIL にしない）。

## 合格条件

- 110 ケースすべて期待どおり。FAIL 0。既存回帰（unit / 静的ガード / e2e_audio_export）も緑。

## 想定リスク

- 抜粋素材は元ファイル先頭20秒のパケットコピーで、音声は元と同一パケット。
- 相関オラクルは実音声の性質に依存するため、パイロット校正で閾値と区間を固定する。
- コンテナ timestamp は edit list を尊重するプレイヤー前提（実プレイヤー聴感は既知の制約）。
- プレビューは全長焼き込みのため、切り出し区間（IN/OUT）はプレビューでは検証しない（既存仕様）。
